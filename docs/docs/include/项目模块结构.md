<!-- 项目模块结构 -->

IoT 统一接入平台：项目使用 gradle 进行打包

**common:** *公共类*
  - adapter interface（Adapter的接口定义，方便core进行调用）
  - 实体类
  - 通用处理逻辑
  - utils

**frost-iot-core:** *核心模块（可以运行在客户端 / 服务端，支持级联；与管理后台无关，可独立运行）*
  - 与管理后台交流的模块
  - self-update: 内置更新工具
  - cascade: core 模块级联（支持通过多个 adapter 进行级联；智能感知当前core节点的拓扑结构，及在级联树状结构的哪一层；最终形成一个拓扑结构《考虑上级节点配置是否允许下级节点查看其拓扑结构》）
  <!-- > 使用 Netty 构建 HTTP 服务 -->

**frost-iot-adapter:** *适配器（独立模块）*
  - private-protocol-adapter: 私有协议适配器
  - webhook-adapter: WebHook 适配器
  - mqtt-adapter: MQTT 适配器
  - websocket-adapter: Websocket 适配器

**manager:** *管理后台*
  - backend: 管理后台（后端，无需内置Core模块）
    > 使用 Spring Boot 构建 HTTP 服务
  - frontend: 管理后台（前端）

模块说明（文档中添加《预估内存占用》说明）：
- core是核心模块，adapter是适配器，manager是用来查看的简单模块
- core 可以部署在硬件附近的 linux 小盒子中，也可以部署在服务器端，支持级联。
- adapter用于接收硬件数据后传递给 core 模块进行处理。（core模块内置几种最常见的adapter）
- manager可以与 core 模块进行交流，可以部署在服务器上。
